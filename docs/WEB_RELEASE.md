## PWAの更新・トラブル対応

- Web成果物の内容からビルドIDを生成し、Service Workerへ埋め込みます。次の公開で静的ファイルが変わればキャッシュ名も変わります。
- ビルダーが静的ファイルのSHA-256一覧もWorkerへ埋め込みます。インストール時は全ファイルを取得・照合してからキャッシュへ保存します。CDN等から異なる版が返った場合や取得失敗時は、新Workerを有効化しません。
- 初回にService Workerとmanifestを登録します。既存の登録がある端末でも、URLは同じ`sw.js`を使います。
- 新Workerは待機し、利用者に全タブとホーム画面アプリを閉じるよう案内します。`skipWaiting()`による学習中の即時切替はしません。初回訪問は次の表示からWorkerに制御される場合があります。
- キャッシュ削除はこのアプリのscopeを含む名前だけに限定します。他サイト内アプリや古いグローバルキャッシュは削除せず、新Workerはそれらを読みません。
- Firebase・Sheetsへの要求やBot等の未許可パスをWorkerでキャッシュしません。オフラインで画面が開いても、Sheets取得・認証・履歴保存には通信が必要です。
- 制御中の静的ファイルがキャッシュから欠落した場合は503を返し、ネットワークの新しいJS/HTMLを代わりに混ぜません。URLにクエリが付いても同じ版の資産として扱います。保存領域不足・削除等でこの状態になった場合は、更新手順または最終手段のWorker再登録で復旧します。
- ソースディレクトリの`sw.js`には検証用のハッシュ一覧がないため、そのまま公開しても新Workerのインストールは停止します。必ずビルド済みの13ファイルを公開してください。
- 更新しない場合、PCではDevTools → Application → Service Workers / Cache Storageでscope、待機Worker、buildIdを確認します。iPhoneでは全タブ/PWA終了後の再起動を先に試します。
- SafariのWebサイトデータ消去やWorker登録解除は最終手段です。ローカル認証状態が消えて再ログインが必要になります。Firestoreの保存済み履歴を削除する操作ではありませんが、未保存の学習結果は失われるため、利用者の確認後だけ実施します。
- 問題発生時はbuildId、端末・OS・ブラウザ、操作順、期待/実際の結果を記録します。過去の既知の安全なコードへ戻す場合も、main反映・再ビルド・デプロイの別途承認が必要です。FirestoreやSheetsのデータを巻き戻す手順にはしません。

## ロールバック計画（承認後にのみ実施）

1. 初回公開前に、現在公開中の版のコミット、Pages実行ID、動作確認結果を記録します。旧版は新ビルダーを持たないため、既知の正常なWeb資産を安全なビルド手順へ取り込んだ**11ファイルだけの復旧候補**を別途検証して保管します。リポジトリ全体を旧方式で再公開してBot等の公開を復活させないでください。現在のローカル成果物のバックアップは、過去の本番版のバックアップとは区別します。
2. 新方式の正常な公開実績ができた後は、その実行ID・ソースコミット・`release.json`・Web専用成果物を保存します。現設定のレビュー成果物保存期間は7日なので、必要な復旧期間に合わせて本人管理の保管も用意します。
3. 障害時は追加の学習試験・Bot操作を止め、Web版だけを戻す範囲を決定し、復旧デプロイの承認を得ます。Firestore・Sheets・認証アカウントを削除・巻き戻しません。
4. 正常だった**新方式の手動実行**を再実行する場合、GitHub Actionsは元の`GITHUB_SHA`/`GITHUB_REF`を使用します。履歴の対象SHAが意図した版か必ず照合し、**Re-run all jobs**でPages公開元ガードと成果物検査を通して再ビルド・再公開します。成果物名は実行ID・試行番号付きで、過去の成果物を上書きしません。deployジョブだけの再実行は新しい試行の成果物を持たないため使用しません。承認済みの旧成果物を再配信する専用経路は、現ワークフローには追加していません。
5. 過去の手動実行がない初回の障害や、旧コードがビルダー非対応の場合は、復旧候補を使う修正コミットをレビューして、承認後にmainへ反映・手動デプロイします。単純な`git reset`、force push、データ初期化は使いません。
6. 復旧後も同じURLです。`release.json`、現在のWorkerのbuildId、静的ファイル公開範囲を確認します。利用者には全タブ/PWAを閉じて開き直してもらいます。ローカル認証状態を消す操作は最終手段として本人同意を得ます。

参考: [ワークフロー再実行](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/re-run-workflows-and-jobs)。
