# ChatGPT ⇔ Codex 開発引き継ぎ

GitHub の `docs/ai-handoff/` を引き継ぎの共通参照先とします。確認するブランチやコミットを指定してください。会話だけで合意した仕様は、リポジトリの記録に反映されるまで提案として扱います。

| ファイル | 役割 |
| --- | --- |
| [HANDOFF.md](HANDOFF.md) | 次の会話に渡す要約、対象リビジョン、優先タスク、承認待ち |
| [STATUS.md](STATUS.md) | コード、ローカル検証、本番確認を根拠とともに記録 |
| [BACKLOG.md](BACKLOG.md) | 安定した項目ID、状態、着手順、依存関係、完了条件 |
| [DECISIONS.md](DECISIONS.md) | 有効な決定、採用理由、保留案、仕様変更履歴 |
| [ARCHITECTURE.md](ARCHITECTURE.md) | 現在のデータ経路、運用、互換性制約 |

次段階の定量比較・照合・依存監査・実機確認資料は [バックログ](BACKLOG.md#次段階の追跡資料) から参照できます。

## ChatGPT から Codex へ

1. 候補仕様を検討し、決定事項、未決事項、該当するバックログID、承認済み操作を区別して渡します。
2. Codex は作業ディレクトリ、ブランチ、HEAD、未コミット変更を確認し、上表と根拠資料を読みます。依頼に含まれる決定事項は実装前に `DECISIONS.md` に記録します。
3. `BACKLOG.md` で対象と状態を確認し、凍結解除は利用者の明示指示を記録してから行います。

## Codex から ChatGPT へ

1. 実装完了、仕様変更、不具合の発見・修正、検証完了、中断、凍結状態の変更時に資料を更新します。
2. `STATUS.md` にバックログID、変更内容と理由、対象ファイル、試験の範囲・結果、残存リスク、完了条件、次の作業を記録します。`HANDOFF.md` に影響の大きい内容を要約します。
3. 共有済みなら GitHub のブランチまたはコミットと `HANDOFF.md` のURLを渡します。未共有なら、次を実行し、標準出力を確認してから会話へ貼り付けます。

   ```sh
   node scripts/print-ai-handoff.mjs
   ```

   補助コマンドはレビュー済みの要約本文と、ローカルGitのブランチ・HEAD・変更有無を標準出力に表示します。任意の差分、未追跡ファイル名、Gitログ、環境変数、運用データを取り込む機能はなく、テストや公開の状態は本文に明記した検証に基づきます。

## 記録の基準

- 日時にはタイムゾーンを付記します。未コミットの場合は対象の起点SHAと「作業ツリー」を明記し、文書自身のコミットSHAを本文に埋め込む必要はありません。
- 実装とローカル検証と本番確認はそれぞれ証跡を残します。過去の件数には確認日と対象環境を添えます。
- 資料へ載せるのは共有できる技術情報です。資格情報、個人情報、非公開教材、ローカルの秘密設定や監査ログは記載対象外です。
- 資料更新、ローカルコミット、push、PR作成、mainマージ、デプロイは個別の操作です。承認の範囲は [AGENTS.md](../../AGENTS.md) と [HANDOFF.md](HANDOFF.md) を参照してください。
