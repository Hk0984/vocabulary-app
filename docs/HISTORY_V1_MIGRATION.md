# 世界史分類v1：実装と移行手順

**方針変更後の優先手順は [HISTORY_REBUILD.md](HISTORY_REBUILD.md)。旧430問の管理12→16列移行は必須ではなく、新しい管理16列・公開13列を別ブックで構築する。以下は旧方式を移行する場合の参考記録であり、現在の必須手順ではない。**

この文書の移行操作は今後の明示承認後に本人が実施する。今回の作業はローカル実装・モックテスト・CSVドライランまで。本番Sheetsの読み書き、Discord接続、Bot起動、コミット、push、公開は未実施。

## 形式と互換性

- Webは専用公開シートの正確な9列・13列ヘッダのみを受け付ける。10〜12列、14列以上、管理列入りのヘッダは拒否する。通常単語用シートを代替公開先にしない。
- 公開13列：旧9列 + `period_codes,century_codes,area_codes,time_ranges`。
- 管理16列：旧9列 + `status,batch_id,created_at` + 分類4列。**statusはJ、batch_idはK、created_atはLのまま**。
- 旧CSV9列は13列内部形式へ補完する。BotのライブI/Oは移行後の管理16列／公開13列だけを許容し、旧・混在ヘッダのままでは書かない。
- IDは文字列のまま。既存のゼロ埋めID、本文、選択肢、正答、作成日時を維持する。CSV入力でも本文の外側空白を勝手に除去しない（空白だけの必須値は拒否）。
- 旧行の追加値は `unclassified`, 空欄, `unclassified`, 空欄。完全な空行は空行位置を維持する。
- Firestoreは `users/{uid}/progress/history_questions` / `history_<id>`、既存フィールド、トランザクション保存を維持する。Rulesの変更・履歴移行は不要。英語・古文のパーサー、語彙の問題生成は変更しない。

## 学習と分類

語彙モードと世界史のモード・問題数はセッション内で別に保持する。世界史を経由して英語・古文へ戻っても、意味表示・出題形式・ID範囲・問題数・学習モードを復元する。

世界史一問一答を専用公開シートの仮想ジャンルとして1件表示する。独立リンクも学習設定へ誘導する。通常・苦手（誤答率41%以上）・間違い・未学習、10/20/30/50/全件を使用する。未ログイン・匿名は保存せず学習可能。ログイン済みで履歴読込失敗中は履歴依存モードを停止し、通常学習の保存も既存の保護機構で停止する。

各分類軸内はOR、軸間はAND。地域は親→子孫だけに展開する。親のチェックは子孫をチェックし、子を外すとその子を含む親指定も解除する。子から親を自動選択しない。親の一部選択状態を表示する。「全範囲」は選択なしで、個別の全コード選択はglobal/未分類を含めない。非activeの既存コードは読込継続可能（新規のチェック一覧では表示しない）。

世紀チェックは問題データに明示登録された世紀を表示する。年代だけがあり世紀欄が空の問題は、世紀の指定時に含めない。異なる年代で時代と世紀がそれぞれ一致するだけの問題も除外する。未分類を含む問題は分類フィルタを1つでも指定したときに除外する。

時代は学習上の便宜区分。先史は-3501以前、古代は-3500〜500（年0なし）、中世501〜1500、近世1501〜1800、近代1801〜1918、現代1919以降。文字の成立が各地で同年という意味ではない。

負荷制限：年代は絶対値100,000年以内、1セル64区間・2,048文字以内。分類コードは2,048個・24,000文字以内、時代CSV欄は256文字以内。世紀番号は年代上限に合わせ1〜1000（`ce_101`等にも対応）。地域マスター最大4096ノード。Bot入力CSVは既存1MB制限、オフラインCSVは各10MiB・10万データ行以内。範囲は年単位で全走査せず、区間と世紀単位で判定する。

## オフラインの移行ドライラン

地域マスターの階層上限は64。循環判定は再帰に依存せずトポロジカル順で行い、深すぎるマスターはUI描画前に拒否する。

本番接続や認証情報を一切使わない。CSVは同時点の管理・公開のペアを使う。入力を上書きせず、存在しない出力ディレクトリを指定する。

```powershell
bot/.venv/Scripts/python.exe -B scripts/migrate-history.py --management PRIVATE_BACKUP.csv --public PUBLIC_BACKUP.csv --out dist/history-migration-review --dry-run
```

出力は `management.csv`, `public.csv`, `report.json`。ネットワークSDKもライブ書込みモードもない。公開済みID集合と公開先ID集合、本文・分類、重複、列順、既存セルの保存を照合する。不一致時は出力前に停止する。12/9列ペアまたは16/13列ペアのみを許容し、片方だけが移行済みの入力は拒否する。既に移行済みのペアを再変換しても同じCSVとなる。公開行の削除・再作成による修復は行わない。

## 承認後の本番移行順序

1. **準備**：mainのレビュー済みSHA、現在配信中のWeb専用成果物とハッシュ、Pages設定、Botコード版を記録する。管理・公開両方の全CSV、正確なヘッダ、行順・空行、共有権限、Botの設定項目名を別保管する。秘密鍵・トークンはWebやGitへ渡さない。Firestore履歴は削除・リセットしない。
2. **先にWeb互換版**：9列と13列を両方読める今回のWebをレビュー・テスト後、別途承認を得て公開する。今回から公開許可リストは **13ファイル**（従来11 + `history-classification.js` + `history-regions.json`）。`bot/`、CSVバックアップ、指示書、テスト、ログ、認証情報は含めない。
3. **端末確認**：PC/iPhoneで新しいbuildIdを確認し、全タブ・PWAを終了後に開き直す。旧9列専用のWorker/画面が残る端末を把握する。更新前端末はシート13列化後に歴史を読めなくなり得るため、完全無停止とは約束しない。保守時間帯と更新案内を用意する。
4. **停止と再バックアップ**：Botを停止し、1シートにつき1インスタンスであることを確認する。手動編集も止め、管理・公開の同時点CSVを再取得する。オフラインドライランを行い、ID集合と全既存セルの一致・差分レポートを本人が確認する。不一致は原因調査を先に行い、移行しない。
5. **列追加**：別途書込承認後、対象ブックIDを本人が照合する。管理はM〜P、公開はJ〜Mだけに分類ヘッダと補完値を追加する。既存A〜L/A〜I、行順、ID、状態、作成日時は触らず、行の削除・再作成もしない。管理用は限定共有、専用公開用だけをWebから読ませる。
6. **再照合**：変更後の両CSVを再取得し、16/13列ペアでドライランする。既存列の差分0、公開済みID集合の一致、分類の一致を確認する。Webの件数・旧履歴の表示と、通常の英語・古文が維持されることも確認する。
7. **Bot再開**：新Botコードの読み書き範囲A:P/A:MとJ列更新を確認してから、1インスタンスだけ再開する。Bot再起動は別途承認が必要。`/check`等の読み取り、次に本人承認済みの専用検証IDに限ってimport→check→publish→アプリ→deleteを試す。既存問題は削除しない。

## 復旧

- 分類データ不一致ならBotを停止し、ライブ書込を追加せず、前後CSVと差分を照合する。Firestoreには触らない。
- Webだけの不具合は、**9/13列互換を維持する既知の正常版**へ戻す。新シートに旧9列専用Webを再配信しない。
- 旧Botへ戻す必要がある場合は、先にBotを止め、シートも旧12/9列に戻せることを本人が確認する。追加分類列だけを除く復旧候補をオフラインで作成し、元のA〜L/A〜Iがバックアップと同一であることを検証する。移行後に新規問題・編集・公開状態変更がある場合、過去CSV全体を戻して上書きしない。差分を個別にレビューし、復旧にも別途書込承認を得る。
- 端末のPWAは対象scopeの更新を優先し、全タブ/PWA終了→再起動する。localStorage/IndexedDBや学習履歴の一括削除はしない。実機のキャッシュ切替試験は別工程。
